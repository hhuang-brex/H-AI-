# References — Agent Skill Authoring

Sources behind [skill-text-authoring](../concepts/skill-text-authoring.md). Also backs [skill-injection-decision](../concepts/skill-injection-decision.md) and [skill-lifecycle-and-drift](../concepts/skill-lifecycle-and-drift.md). Fetched and confirmed **2026-08-08**; the TRUSS and Skill2Query entries were added and verified in a second pass on **2026-08-18**; the *injection question*, *lifecycle* and three security entries were added and verified on **2026-09-11**. **Every arXiv entry here is a 2026 preprint beyond the May-2026 cutoff, and none is independently reproduced** — all figures are author-reported. ## The vendor guidance — the only prescriptive primary source

- **Skill authoring best practices** — Anthropic (fetched 2026-08-08). https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices — Note the redirect: `docs.claude.com/en/docs/agents-and-tools/…` 302s to `platform.claude.com/docs/en/…`. The most concrete authoring source available, and the origin of several claims in the concept node:
  - **Economy.** "The context window is a public good"; the default assumption is that Claude "is already very smart," so each piece of content must answer "does this paragraph justify its token cost?" Worked contrast: ~50 tokens vs ~150 for the same PDF-extraction instruction.
  - **Degrees of freedom.** Match specificity to task fragility — high freedom (prose heuristics) / medium (pseudocode, parameterized scripts) / low (one exact command, "do not modify the command"). Analogy: narrow bridge with cliffs vs open field.
  - **Hard limits.** `name` ≤ 64 chars, lowercase-hyphen only, no XML tags, no reserved words ("anthropic", "claude"); `description` ≤ 1,024 chars, non-empty, no XML tags. Body **under 500 lines** "for optimal performance."
  - **Descriptions.** Third person always ("Processes Excel files…", not "I can help you…") because the description is injected into the system prompt; must state **what it does and when to use it**, since it is what selects among "potentially 100+ available Skills."
  - **Structure for partial reads.** Keep references **one level deep** — with nested references Claude "might use commands like `head -100` to preview content rather than reading entire files, resulting in incomplete information"; add a **table of contents to reference files over 100 lines**; name files descriptively.
  - **Process.** Build evaluations *before* extensive documentation (identify gaps → three scenarios → baseline without the skill → minimal instructions → iterate); develop with a "Claude A authors / Claude B uses" split; test across Haiku, Sonnet, and Opus because what suits Opus may under-serve Haiku.
  - **Navigation signals to watch.** Unexpected exploration paths, missed connections (references not followed), overreliance on one file (promote it into the body), and content never accessed (cut it or signal it better).
  - **Anti-patterns.** Time-sensitive conditionals (use an "old patterns" section), offering many library options instead of one default plus an escape hatch, Windows-style paths, inconsistent terminology, "voodoo constants" in bundled scripts, and scripts that defer error handling to the model.
  - Also ships a **plan-validate-execute** pattern (verifiable intermediate artifact, validated by script before anything is applied) and a checklist for review before sharing.

## Valuing and improving skill text

- **What Is a Skill Worth? Structure-Aware Shapley Valuation of Agent Skills** — Li, Liu, Zhao, Li, Wang, Shao, Liu, Shou (2026-08-05). https://arxiv.org/abs/2608.04562 — The measurement counterpart to authoring. Defines **skill valuation**: assigning credit to a fixed skill's *internal units* — rules, examples, scripts, heuristics — under a fixed agent and held-out task distribution, and argues it differs from data- or prompt-span valuation because skill units "may depend on other units, belong to a document hierarchy, trigger agent behavior, and consume limited prompt context." **SkillSV** compiles a skill into units + dependencies + hierarchy so only *valid* counterfactual skills are evaluated, and uses **paired deletion with length-neutral padding to separate content value from context cost** — the fix for the confound in naive ablation, where deleting a rule also shortens the prompt. The most directly useful entry for deciding what to cut.

- **SkillHEX: Improving Agent Skills via Hypothesis-Driven Autonomous Exploration and Exploitation** — Feng, Chen, Zhao, Zhang, Wang, Lu, Wang, Xu, Li, Chen (2026-08-06). https://arxiv.org/abs/2608.05628 — Frames the diagnostic problem precisely: at test time, with limited interaction budget and no train/validation split, outcomes are a **sparse reward that conflates multiple latent failure causes**, and methods that "greedily refine a single incumbent skill" fall into an **exploitation trap** where "early misdiagnoses exhaust limited trials along unproductive trajectories." Remedy: translate falsifiable failure hypotheses into executable tests, and search with evidence-guided tree search. Read it as the argument for testing a hypothesis before rewriting a rule.

- **Progressive Agent Skill Generation via Reinforcement Learning** — Shen, Zhang, Guo, Cheng (2026-08-03). https://arxiv.org/abs/2608.01678 — Notes that skills "lack a natural supervision signal based on relevance or correctness; their value can largely be determined only by whether they improve the behavior of the agent on downstream tasks," and formulates skill generation as **sequential editing decomposed into individually evaluable edits** (Skill-α). The structural lesson survives the RL machinery: make each edit separately scorable. Code: `ejhshen/skill-alpha`.

- **ContinualSkillBench: Can LLM Agents Truly Evolve Their Capabilities?** — Guan, Wang, Yang, Cao, Liu, Hu, Li, Zhang (2026-08-04). https://arxiv.org/abs/2608.03874 — The control every skill-authoring effort needs. Five domains × 100 interconnected subtasks ordered by difficulty with cross-task reuse opportunities. Findings: sequential execution generally helps but "gains vary substantially across models and domains," and **in-context learning performs comparably to explicit skill maintenance on average**, suggesting much of the improvement "arises from adaptation to prior context and feedback rather than reusable skill a[cquisition]." Cite it whenever a skill library's value is asserted rather than measured.

- **TRUSS: Towards Task-Reliable and User-Safe Automated Agent Skill Generation** — Zhang, Ouyang, Shi, Wang (2026-08-18). https://arxiv.org/abs/2608.17588 — The acceptance-testing counterpart to authoring, and the sharpest statement of why text review is insufficient: evaluating a candidate skill "solely from its artifact or final task outcome leaves unresolved which actions the equipped agent will perform and which side effects those actions will produce." TRUSS checks functional claims against source and domain evidence, screens the whole artifact against **nine predefined safety properties** as a static gate, then loads survivors into a **shadow agent inside a Controllable Execution Environment** where brokered tools expose requested actions to policy enforcement and record them. The recorded action list is the acceptance artifact — see [dry-run-and-preview](../concepts/dry-run-and-preview.md).

## Rule structure and its failure modes

- **Confidently Wrong: Exception Chain Collapse in Frontier LLM Rule Evaluation** — Simpson, Kozak, Doake (2026-07-25; working paper v3.13.0, 43 pages). https://arxiv.org/abs/2607.23386 — Documents **exception chain collapse** under nested conditionals of the form "A is required UNLESS B applies, UNLESS C overrides B," in eligibility evaluation. Two takeaways: don't write nested exceptions in skill text, and note the operational warning — "between March and April 2026 several failure cells closed silently under the same model alias, with no version bump (GPT-5.4 on construction insurance moved from 96.6% to 100%, same prompt and harness)," so "frontier-model accuracy is a moving compliance boundary that shifts without notice." Their architecture has LLMs author rules from authoritative sources and an **SMT layer execute them deterministically** — the pattern in [llm-as-autoformalizer-plus-solver](../concepts/llm-as-autoformalizer-plus-solver.md). Artifacts: `Aethis-ai/confidently-wrong-benchmark`.

- **IFHierBench: Hierarchical Instruction Following for Large Language Models** — Mao & Chen (2026-07-30). https://arxiv.org/abs/2607.27912 — 600 prompts stratified across four constraint-tree depths and 35 distinct constraints, each with a **deterministic checker**. Its critique is the reusable part: existing instruction-following benchmarks "treat the constraint set as a flat list applied uniformly to the response, so they cannot scope a check to a particular section of the output." If a skill specifies a layered artifact, attach each rule to the section it governs. Pairs with *Instruction Stacking Collapse* ([arXiv:2608.02639](https://arxiv.org/abs/2608.02639)) in [references-prompt-attribution](references-prompt-attribution.md).

## What developers actually maintain (adoption evidence)

- **A Study of Cursorrules Files in GitHub Open Source Projects** — Sun, Akhoundali, Kudriavtseva, Karayalcin, Gadyatskaya (2026-08-11; **ICSOFT 2026**, author copy). https://arxiv.org/abs/2608.10622 — The adoption datapoint for standing instruction files: **12,110 `.cursorrules` files from 11,427 GitHub repositories**, characterizing distribution, evolution, and maintenance, plus qualitative analysis of 65 files yielding a **65-code codebook** of what developers put in them. Frames the artifact class precisely — modern tools "combine dynamic conversational prompts with static configuration-like prompt files," and research has concentrated on the conversational half while "prompt files remain understudied."

- **An Exploratory Study of Agent Plans for Agentic AI Coding Tools in Open-Source Software** — Abubakar, Mohsenimofidi, Lulla, Zhang, Treude, Baltes, Galster (2026-08-05; **ESEM 2026**, Emerging Results track). https://arxiv.org/abs/2608.04661 — The contrasting datapoint, and the reason to invest authoring effort in the standing file rather than the plan: screening **36,710 GitHub repositories** yielded only **85 Markdown plan files from 10 repositories** — "a highly concentrated corpus." Distinguishes repository-shared *context* files (AGENTS.md-style project conventions) from task-oriented **Agent Plans**, and finds the latter is barely a practice. Read the two studies together in [skill-text-authoring](../concepts/skill-text-authoring.md).

## The document as a retrieval object

- **Skills Know Their Neighbors: Cluster-Contrastive Capability Pages for Skill Retrieval** — Wang, Wen, Ji, Qiao (2026-08-05). https://arxiv.org/abs/2608.04482 — Sharpens "the description is the routing function" into something actionable. Formalizes a skill's capability as its **executable region** — the set of queries it can solve — and its document as "a lossy observation of that region," which "exposes a document-imposed component of retrieval error that cannot be removed by improving the retriever alone." Proposed **Capability Pages** carry a positive trigger *and* a **negative boundary** — which similar-looking requests should be routed elsewhere. Actionable edit: state what the skill is *not* for, especially against its nearest neighbors.

- **Comparative Approaches to Agent Retrieval over Large Skill Libraries** — Kolluru & Sportsman (2026-08-06). https://arxiv.org/abs/2608.06196 — Scale reality check over **690 skills / 117 realistic non-echoing queries**: a hybrid lexical + dense ranker puts the correct skill in the top five in **73.5% ± 8.0** of cases, "leaving roughly a quarter of queries unserved," and a typed workflow knowledge graph was **significantly worse at matched token budget (−11.2 points)** when substituted for additional ranked results. Grounds the skill-sprawl pitfall in [agent-skills-progressive-disclosure](../concepts/agent-skills-progressive-disclosure.md): past a few hundred skills, discovery — not authoring — is the binding constraint.

- **Skill2Query: Exploiting Skill Structure to Generate Pseudo-Queries for Agent Skill Retrieval** — Ding, Guo, Lu, Zhou, Zhou, Zhang, Lin, Ge (2026-08-17). https://arxiv.org/abs/2608.16071 — Attacks the supervision bottleneck for skill retrieval by parsing a skill document into a **Skill Knowledge Graph** and generating pseudo-queries via style mimicking → query-template generation → parameter filling, arguing that document-level approaches "leave the rich internal relations among capabilities, parameters, and usage examples implicit" so queries end up topically relevant but lacking **capability grounding and parameter consistency**. Authoring implication: the internal structure of a skill document (capabilities, parameters, examples) is machine-consumable — write it explicitly rather than as prose.

> **Name collision — check the arXiv id, not the name.** *SkillZip* now names at least **three** unrelated 2026 arXiv entries; the third, *SkillZip Pro* ([arXiv:2608.30785](https://arxiv.org/abs/2608.30785), Bai, Liu, Lin, Wu, Song, Jin, 2026-08-31), shares a lead-author surname with the second but its lineage was not established — cite by identifier in every case. The first two, six days apart with different author teams: [arXiv:2608.05604](https://arxiv.org/abs/2608.05604) *Contract-Preserving Graph Compression for Scalable Agent Skill Libraries* (Tan et al., below) and [arXiv:2608.11079](https://arxiv.org/abs/2608.11079) *Evaluation-Free Skill Compression for Self-Evolving Agents by Discovering Reusable Structure* (Bai et al.). Both are cited in this list; neither is a version of the other. Verified 2026-08-30.

- **SkillZip: Evaluation-Free Skill Compression for Self-Evolving Agents by Discovering Reusable Structure** — Bai, Lin, Liu, Zhang, Jin, Cao, Li (2026-08-11). https://arxiv.org/abs/2608.11079 — The most useful entry for deciding *how* to shrink a skill, and the source of the ceiling on measuring line value. Its argument against generic prompt compression: a skill "is not a flat passage — its name and description define when it applies, its workflow controls execution, its tool and output contracts constrain validity, and **rare exceptions may remain essential even when no sampled task activates them**." Evaluation-guided compression can test behaviors but "introduces rollouts, cost, and dependence on the compression-time evaluation set." Their alternative is evaluation-free: compress to "the shortest faithful structural explanation" — **explain once, reference many**, stating a repeated rule once at the scope that governs it. Grounds the restructure-before-delete rule in [skill-text-authoring](../concepts/skill-text-authoring.md).

- **SkillZip: Contract-Preserving Graph Compression for Scalable Agent Skill Libraries** — Tan, Wang, Liu, Xu, Yuan, Zhu, Zhang (2026-08-06). https://arxiv.org/abs/2608.05604 — Names a **unit mismatch** worth internalizing: "skills are retrieved as packages, compressed as text, and converted into execution graphs only after retrieval, whereas reliable reuse requires a contract-bearing procedural unit." Performs contract-preserving compression over **section-level** graphs, so compressed routines stay executable and expandable as skills evolve. The argument for writing skills in self-contained sections with explicit contracts rather than continuous prose.

## Does the skill help at all? (the injection question)

Added 2026-09-11. These four are the evidential basis of [skill-injection-decision](../concepts/skill-injection-decision.md).

- **Signal or Noise? A Benchmark Study of Agent Skills in Web Development** — Yang & Ding (2026-08-24). https://arxiv.org/abs/2608.23067 — The negative control this graph was missing. Its premise: because every injected skill expands the prompt of every query, "an effective Skill benchmark must determine not only whether an agent can solve a task, but whether the Skill should have been injected at all." Over **31 public WebDev skills × 50 Web-Bench projects × 1,000 ordered tasks × 4 models**, with a **length-matched irrelevant control** and leave-one-out ablations, and with only `SKILL.md` in the prompt (auxiliary files mounted in the workspace): matched skill injection **reduced mean Pass@2 by 1.3%–4.2%**, raised token cost **72%–394%**, and helped in only **17%–36%** of skill-project pairs. Two separable failure modes — **length-distracted** (an equally long irrelevant skill reproduces most of the loss) and **content-misled** (length neutral, content still costs 1.1%–1.4%). Also: losses concentrate on *easy early* tasks, rankings transfer weakly across models, and **anti-pattern rules outperform example-heavy content** in helpful skills. Scope: third-party public skills, coding-agent domain — it does not measure a hand-written domain playbook.

- **Grounded Checklist Partial Credit for Agent Skill Trajectories** — Qin, Yin, Wang (2026-08-26). https://arxiv.org/abs/2608.27487 — The instrument that makes the above measurable, on the premise that "a skill can alter execution without changing the final outcome." Humans define reusable rules once; an LLM instantiates a task-specific checklist grounded in the instruction and the official verifier; a judge scores each item **from execution-log evidence alone and abstains when evidence is missing**; a separate scripted step applies the verifier outcome. Beats holistic judging at discriminating official PASS/FAIL (**AUC 0.689 vs 0.619**) over 4,455 deduplicated SkillsBench trajectories, aligns better with humans on 96 trajectories / 12 tasks, and transfers to Terminal-Bench and SWE-bench. The headline number for binary scoring's blind spot: among **879** with/without-skill pairs whose binary outcome was unchanged, **20.9% improved by >0.10 and 18.7% regressed by the same margin**.

- **Subagents vs Agent Skills: Executing Reusable Knowledge for Long-Horizon Agentic Tasks** — Piriyakulkij, Lawrence, Curth, Karmalkar, Prasad (2026-09-07). https://arxiv.org/abs/2609.09233 — Questions the default that a skill is *text loaded into context*. As horizons grow, in-context skill execution "becomes increasingly brittle, because reasoning quality degrades as more information accumulates in the context window"; invoking the skill package as a **subagent** spawns a fresh window per subtask instead. Reported to win **when skill packages expose clear input-output contracts and their instructions encode the procedural knowledge needed to fulfill those contracts**, at the cost of coordination tokens. Conclusion worth quoting: "the benefit of reusable knowledge depends not only on its content, but also on how it is organized and invoked." No numbers in the abstract, no venue.

- **SE-GoS: Self-Evolving Graph-of-Skills for Skill Library at Scale** — Fu, Jiang, Qian, Wang, Hao (2026-09-08). https://arxiv.org/abs/2609.08228 — The routing alternative to always-loading, and **training-free**: evolve an existing skill-retrieval graph from execution traces via topology evolution, edge-weight reinforcement, and **description evolution**, with no change to the retrieval algorithm or the skill content. One evolution round: reward **52.4% → 59.4%** with roughly **one-third fewer input tokens** than full skill loading, and the evolved graph transferred to a disjoint held-out split for **+5.4 points** over static GoS. Three LLMs on SkillsBench; gains vary by model family. Note which artifact it optimizes — the retrieval-facing description, i.e. the routing contract.

## Lifecycle — staleness, closure, and compression as a standing cost

Added 2026-09-11. Backs [skill-lifecycle-and-drift](../concepts/skill-lifecycle-and-drift.md).

- **Repo2Skill-Evo: Repository Skills Go Stale in Silence** — Duan, Shi, Mao, Zhang, Liang, Piao (2026-08-22). https://arxiv.org/abs/2608.21964 — The mechanism, stated better than this graph had it: "the same version specificity that makes a skill useful also makes it fragile," so "externalizing knowledge into a skill can therefore make its decay invisible." Casts each release as a skill-maintenance task (V1 skill set + official V1→V2 patch → update the obsolete, preserve the valid). Across **57 real-world repositories and 105 release transitions, every evaluated transition invalidated part of the V1 skill set**, and six frontier agents reached only **29.9%–69.7% avg@3 macro F1** under a patch-grounded removal metric balancing stale-content recall against over-editing precision. The two dominant errors are opposite — incomplete file coverage leaves stale content, overbroad editing trades precision for recall — which is why a one-sided maintenance metric rewards over-deletion.

- **ClosureBound: Versioned Transitive Dependency-Closure Binding and Operation-Time Effect Governance for Agent Skills** — Zhu & Wang (2026-09-05; 30-page preprint). https://arxiv.org/abs/2609.05920 — Why a directory pin is not an identity: skills "combine instructions with files, packages, tools, models, and services, so operational identity can exceed a signed directory," and "recursive or lazy dependencies may change while root-level evidence remains valid." Proposes a reference monitor binding each grant to an exact closure root with an effect ceiling, establishing **version non-inheritance** and **effect non-amplification** among other properties (explicitly *not* program equivalence or remote-service honesty), validated by fixtures and model checking rather than deployment. The immediately usable part is its lexical audit of **549 public skills / 4,872 unique files**: only **21 of 526** roots with bundled files name every non-manifest path verbatim, **67** contain links resolving outside their roots, and **no root declares a frontmatter `dependencies` field**.

- **SkillZip Pro: Execution-Aware Dynamic Compression of Progressively Loaded Skills for Self-Evolving Agents** — Bai, Liu, Lin, Wu, Song, Jin (2026-08-31). https://arxiv.org/abs/2608.30785 — Extends compression from the root file to the **whole progressively-loaded bundle**, on the observation that "compressing only the root misses most deployment cost and may move branch-specific details into the always-loaded context," while flattening destroys the progressive-loading boundaries. Compresses *across* files against the root or a declared environment contract while preserving routing, with One-Shot/Continual (Zip-on-Write after each evolution patch) and Persistent/Transient axes. On a production content-moderation skill: **38% of bundle tokens and 10.4% of end-to-end per-run tokens removed with no quality loss**, while an unprotected **71%** configuration lost **up to 26 accuracy points, one-sided as false positives**. Author-reported on an industrial harness; the transferable points are the cross-file dedup target and the asymmetric failure of over-compression.

## Skill text as attack surface

- **Towards a Risk Assessment of Malicious Skill Files in Coding Agents** — Yang, Fu, Tantithamthavorn, Arora, Chua (2026-08-05; preprint, under review). https://arxiv.org/abs/2608.05223 — "Folders of instructions and scripts that agents load dynamically" widen the attack surface, "letting malicious shell commands hide within natural-language skill files." Contributes an adversarial skill-synthesis method using six LLMs across four families to turn **471 real-world shell commands into 2,826 benign-appearing skills mapped to 11 MITRE ATT&CK tactics**, plus an evaluation pipeline with run stratification, evidence anchoring, a refusal veto, and a deterministic declared-intent override. The concrete basis for treating a third-party skill as untrusted code — see [action-execution-safety](../topics/action-execution-safety.md) and [prompt-injection-and-isolation](../concepts/prompt-injection-and-isolation.md).

- **A Finger on the Scale: Covert Policy Steering through Agentic Skills** — Li, Chen, Zhou, Pu, Ma, Feng (2026-09-02; 25-page preprint). https://arxiv.org/abs/2609.02564 — The threat that output validation cannot see. Frames skills as "externalized behavioral policies" and defines **Skill Policy Integrity**: a skill-induced policy must stay aligned with its declared functionality and the user-authorized objective. SkillShift then violates it *without* command injection or task hijacking — semantically plausible policy edits that preserve the task and a valid output interface while redirecting decisions. Reported **81.33%** and **63.33%** attacker-favored selection rates (agentic commerce; software-dependency choice) at a **100% utility-preserving rate**, transferring across LLM backends and agent environments, with **the evaluated scanners failing to detect** the skills. Its conclusion is the actionable one: audit skills *behaviorally*, as policy artifacts.

- **MaliciousSkillBench: A Comprehensive Benchmark for Malicious Agent Skill Detection** — Wang, Liu, Deng, Zhang, Li, Chen (2026-08-20). https://arxiv.org/abs/2608.19901 — The generalization number to quote whenever a skill scanner is proposed as the control. Consolidates 13 public sources (8,414 raw malicious records → **7,539 normalized-unique identities in 4,588 structural families**) into a 9,740-skill benchmark (7,505 malicious / 2,235 benign). Learned text detectors score **0.882–0.932 macro-F1 under random splits but only 0.653–0.665 source-disjoint**; the strongest (word TF-IDF SVM) keeps **95.6% malicious recall at a 62.4% benign false-positive rate** on held-out sources, and off-the-shelf scanners only cut false positives by sharply losing recall.

- **Scanning the Harness: An Empirical Study of Supply-Chain Defects in AI Coding-Agent Configurations** — Kapner, Soceanu, Petrunin, Gartner (2026-09-07). https://arxiv.org/abs/2609.07360 — Measures the whole configuration layer as a dependency surface "installed from marketplaces and public repositories, running with the developer's privileges, with no lockfile, no install-time check, and no vocabulary for what a component may do." Over **3,171 public repositories** (2,660 multi-component setups, 511 skill collections), counting only byte-decidable rules and validating every finding by independent re-derivation plus LLM adjudication plus a second re-check: **16.0% of setups carry a security defect** — **9.8%** an unpinned MCP server, **3.1%** a scoped-looking blanket execution grant such as `Bash(python:*)`, **3.8%** a skill that pre-approves the shell for its installer (present in 3.7% of published collections). No credential-exfiltration path confirmed. Methodological point worth reusing: the **raw scanner rate was 25.5%** against 16.7% confirmed on the same rules. Tool and every verdict released.

- **SkillSecurer: Detecting and Patching Prompt-Injection Vulnerabilities in AI Agent Skills** — Mecca, Verna, Bouchari, Jha, Mellia (2026-09-12; cs.CR). https://arxiv.org/abs/2609.14079 — The prevalence number for *published* skills, and the first entry here that goes past flagging to **localisation and patching**. A red agent generates context-compatible injections across **nine threat types while recording the exact modification**, so a verifier can compare a scanner's finding *and its patch* against ground truth — injection-level rather than skill-level evaluation, which is the methodological contribution. With its best backend it is reported as the only scanner reaching a **100% injection detection rate**; scanning popular published skills, it finds **latent vulnerabilities in more than 17% of those examined**, and triggers actual incidents on some. Read alongside MaliciousSkillBench above, whose source-disjoint collapse (0.882–0.932 → 0.653–0.665 macro-F1) is the reason to distrust any single scanner's headline rate — including this one's, which is author-reported on its own generated corpus. The transferable design is **recording the injection at generation time so remediation is checkable**, not the detection score.
